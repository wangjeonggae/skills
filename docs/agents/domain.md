# Domain docs

Use a single-context layout:
- GLOSSARY.md at the repository root
- Architecture decision records under docs/adr/

Before exploring, read the glossary and relevant decision records.
If absent, proceed silently; do not create placeholders.
The domain-modeling skill creates them when terms or decisions emerge.

Use glossary vocabulary consistently in issues, proposals, and tests.
Note missing concepts for domain-modeling.
Explicitly flag conflicts with existing decision records;
do not silently override them.
