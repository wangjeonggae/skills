# 需求与验收

选一种输出模式：原文优化、新建 PRD、故事/地图、验收。先读 references/requirements.md。

原文优化沿用原章节、编号、用词及已确认规则，把修订写回对应位置；仅在用户明确要求重构时改整体结构。新 PRD 按复杂度裁剪，小改动可一页。未指定格式默认 Markdown；用户指定企微/飞书/HTML/Word 时按指定渠道实际交付。

把触发条件、可见状态、动作、系统结果、失败恢复与验收连接起来。跨端适配按目标平台记录，不自动把所有项目都扩到全端。独立输出待确认项与修订摘要；未知技术能力、价格或库存策略不得补造默认值。

## 执行约定

- 根据用户的问题只选相关模式，读取下方对应参考；不把所有方法串成固定流程。
- 已确认的业务规则和用户指定格式优先。事实、建议、假设与待确认项分开；缺人数、效果、成本或工时不编数。
- C 端场景检查转化、留存、退款、毛利与履约的取舍，选择实际受影响的指标；不为小改动扩写全套材料。
- 输入充分就执行。缺硬约束时先完成独立可做部分，再集中补问；普通草稿不重复申请批准。
- 用户要求文件时实际创建文件，使用当前可用的平台工具。未写入远端、未运行或未验收时不能宣称成功。
