# 设计前梳理

读现有材料与已确认决定，识别目标、约束、交付物和真正未决的取舍。用户已有批准稿或明确要求执行既定方案时复用授权，直接处理必要细节，不重复全套确认。

1. 对尚未明确的设计选择比较两三个方案，给理由、代价与推荐；只追问会实质改变行为或硬约束的问题。
2. 给能被评审的具体设计，覆盖组件职责、输入输出、状态、失败恢复和适用验证；规模随问题裁剪。
3. 未获授权且选择重大时确认设计；普通可逆草稿可先完成供审阅。已授权整合、修改或已批准设计时继续执行。
4. 需要设计文档时写入用户指定位置或工作区；仅用户明确要求时提交 Git。不能把文件写出或内部设计确认当上线授权。
5. 形成执行步骤并继续实现与验证。当前会话提供规划技能时可按需使用；缺失时直接给简明步骤，不依赖未安装的 writing-plans。

视觉问题可使用当前可用浏览器或设计工具；概念/范围问题使用文字。不要为没有视觉需求的任务强推浏览器，也不要引用不存在的视觉指南。

输入不足时完成可确定部分，再集中说明剩余缺口。验证后报告真实产物、变化和限制，未运行或未写远端不声称成功。
