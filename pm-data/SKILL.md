# 数据与埋点

按诊断、留存、指标体系或埋点模式工作，读 references/data.md。

先核口径、去重键、时间窗、时区、事件版本、端/渠道构成及缺失，再算变化。同比/前后相关性不证明改版因果；整体下降先检查分群权重变化。

需要数据分析报告时生成真实 HTML 或用户指定文件，图表附分母、观察窗和来源。数据健康与结论可信度先记未知，核验后更新，不能沿用模板默认“健康”。SQL 使用实际 schema，缺 schema 时输出逻辑和缺口。

## 执行约定

- 根据用户的问题只选相关模式，读取下方对应参考；不把所有方法串成固定流程。
- 已确认的业务规则和用户指定格式优先。事实、建议、假设与待确认项分开；缺人数、效果、成本或工时不编数。
- C 端场景检查转化、留存、退款、毛利与履约的取舍，选择实际受影响的指标；不为小改动扩写全套材料。
- 输入充分就执行。缺硬约束时先完成独立可做部分，再集中补问；普通草稿不重复申请批准。
- 用户要求文件时实际创建文件，使用当前可用的平台工具。未写入远端、未运行或未验收时不能宣称成功。
